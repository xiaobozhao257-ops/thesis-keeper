# Thesis Keeper 路线图：从演示闭环到使用闭环

写作日期：2026-08-12。基于 `README.md`、`docs/PRODUCT_REVIEW.md`、`docs/PROBLEM.md`、`docs/RELEASE_GATE.md`、`docs/USER_RESEARCH_FORUMS.md` 与代码现状的完整盘点。

一句话结论：产品内核（反后见之明、入口翻译出口确定、不可篡改）是真实且少人做的洞察，P0 工程与文档质量扎实；但当前是**演示闭环（剧本），不是使用闭环（回路）**。本路线图的全部内容都指向同一件事：让用户真的用它记录半年，并在半年后真的被"当初那句话"找上门。

## 一、现状盘点

### 1.1 已实现的能力（P0 基线，后续不得回退）

| 层 | 已实现 |
|---|---|
| 论点 | 自然语言 → 结构化草稿编译（LLM 唯一入口）、草稿人工校正、Schema/Catalog/权重/单位校验、V1/V2 不可变版本与对比 |
| 监控 | 确定性 METRIC_RULE（连续期）、`DATA_MISSING` 不推断、可解释 Health Score、证据时效扣分 |
| 证据 | TEXT/JSON/CSV 导入、内容哈希去重、FACT/AI 解读/规则/决定四层分离、接受/质疑/改映射、被拒证据不计入健康度 |
| 纪律 | 建仓依据声明、弱依据必须写判错条件、退出计划、计划外行动 + 推动因素、逆规则加仓必须写反证 |
| 复盘 | 复盘打开冻结 THEN 版本、延期补证重开、Trigger 口径异议、决策快照 canonical JSON + SHA-256 验签 |
| 镜子 | 行为镜子只报计数与中位数，样本 <3 不给结论 |
| 数据 | RQData Bridge 覆盖 `metricCatalog` 全量指标（含财务四指标），point-in-time 取数，14 个口径测试 |
| 工程 | D1 持久化、按登录身份隔离、可执行迁移、数据库 Trigger 防篡改、五套自动化测试 |

### 1.2 四层闭合状态（沿用 PRODUCT_REVIEW 的框架）

| 层 | 状态 |
|---|---|
| 一、问题是真的 | ✅ 已闭合（`docs/PROBLEM.md`，含具体失败案例） |
| 二、用户是确定的 | ✅ 已闭合（二选一：进阶个人投资者） |
| 三、机制是可信的 | ✅ 已闭合（不可变版本、THEN 冻结、验签、DATA_MISSING 不推断） |
| 四、闭环是通的 | ❌ **未闭合**：真实标的上，指标观测没有录入路径，触发检测在真实使用中不会跳动 |

### 1.3 核心判断

- **问题**：六个页面围绕单个虚构标的（华星智算）和一个硬编码场景（T0–T6）组织；"投资组合"页实际是单标的 Hero 加场景推进器。目标用户持仓 3–10 只，这个形态无法承载真实使用。
- **证据**：指标序列是场景写死（31→19→17）；Bridge 已能取真实财务指标，但 UI 没有任何路径把观测导入并重算规则；首页没有待办提醒，而财报节奏决定一条规则最快约半年才触发一次——没有提醒，用户必然在触发前流失。
- **推论**：P0 证明的是机制可信，下一阶段要证明的是回路可用。所有新增功能必须守住三个立场：LLM 只在入口翻译、失效判定保持确定性、系统不评价不代替不给交易建议。

## 二、P1：落地必需（先让"真实使用"跑起来）

排序依据：不补则使用回路断裂的优先。每条都给出验收标准，进入开发时需追加到 `docs/RELEASE_GATE.md` 的不变量清单。

### P1-A 多标的组合页

- **问题**：目标用户持仓 3–10 只，当前只有单标的演示。
- **做什么**：
  1. `portfolio` 页改为论点列表：名称、资产类型、当前版本号、健康度分数与状态、证据时效天数、待办角标（待复盘 / 证据过期 / 延期到期 / 规则接近阈值）。
  2. 组合级聚合：各状态论点计数、组合平均健康度、待处理事项总数。
  3. 每只标的有独立详情页（复用现有论点详情路由，去掉 demo-thesis 硬编码）。
  4. 场景推进交互仅保留在演示模式下（`scenarioId = cn-equity-demo-v1`），真实论点不显示"进入下一节点"。
- **验收**：同一账号可建 ≥3 只标的的论点并各自独立推进证据与复盘；组合页每个论点卡片的状态与详情页一致；删除演示场景不影响真实论点列表。

### P1-B 持仓记录并与论点绑定

- **问题**：行为镜子的"持有天数 vs 声明周期、触发后仍持有、结果对照"依赖持仓与成本，当前没有输入。
- **做什么**：
  1. 论点下可记录持仓：数量、成本价、建仓日；记录不可编辑，变更走追加行（与决策快照同一不可变机制）。
  2. 决策快照的价格快照（已有）可与成本计算浮盈亏，仅展示，不进入任何规则判定。
  3. EXIT 快照后自动生成"已退出"状态，持有天数以退出日计算（替换现在的"至今"）。
- **验收**：持仓记录不可原地修改（数据库 Trigger 拒绝 UPDATE/DELETE）；EXIT 后行为镜子的持有天数按实际退出日计算；浮盈亏只展示不参与健康度与规则。

### P1-C 首页待办中心

- **问题**：已有提醒类机制（14/30 天证据时效扣分、复盘延期截止、规则接近阈值）但没有任何主动呈现。投入在前、回报极晚的曲线下，没有提醒等于流失。
- **做什么**：
  1. 首页顶部聚合待办：必须复盘、证据时效超期、延期补证到期、规则 1/2 接近阈值、未核验证据待处理。
  2. 每条待办可一键跳转到对应处理页；待办全部清空时显示空状态而非隐藏区块。
  3. 待办由服务端从快照与时效计算，不依赖场景数据。
- **验收**：模拟"证据 30 天未更新"与"延期到期"各出现一条待办并可跳转；待办不包含任何交易建议文案。

### P1-D 指标观测的真实入口

- **问题**：Bridge 已接入 `revenue_yoy` 等财务指标（PRODUCT_REVIEW 行动项 1 的成果），但 UI 无路径取数、确认并重算规则——真实标的的失效检测仍不会跳动一次。这是第四层"闭环未闭合"的直接原因。
- **做什么**：
  1. 论点详情页新增"拉取观测"：按论点 `canonicalCode` 调 Bridge `/metrics`，展示候选观测（指标、周期、数值、point-in-time 查询日）。
  2. 用户确认后追加为观测并重算规则进度与健康度；数值与来源只读，不可手改（防未来函数与篡改）。
  3. 数据不可用（`DATA_MISSING`）时保持现有"不推断、不扣分"行为。
- **验收**：对真实代码确认一期观测后，规则进度与健康度按确定性规则更新；观测落库后不可编辑；Bridge 不可用时显示 `DATA_MISSING` 而非恶化。

### P1-E 论点关闭与接力

- **问题**：现实是"论点失效≠卖出"，用户可能带着新论点换仓（调研 O3）。现在 EXIT 只冻结快照，没有结局记录，也没有从旧论点长出新论点的路径。
- **做什么**：
  1. 关闭论点时记录结局类型：论点失效退出 / 止损 / 按计划退出 / 新论点替换。
  2. 允许从旧论点一键创建新论点（继承标的与部分假设，明确标注为新版本而非改写）。
  3. 行为镜子新增"结局分布"计数（沿用只报计数、样本 <3 不给结论的规则）。
- **验收**：关闭的论点不再出现在组合待办中但保留在历史；新论点与旧论点可见来源链；结局分布样本不足时不显示比例。

## 三、P2：价值深化（决定留存与壁垒）

| 项 | 做什么 | 为什么 |
|---|---|---|
| P2-A 证据抽取接线 | 把 `EVIDENCE_EXTRACTOR` 真正接上 LLM：研报/公告文本 → 结构化事实 + 影响方向；保留人工核验门禁，核验后才计入健康度 | 消灭最大录入摩擦。属于"翻译任务"，与"入口翻译、出口确定"立场一致，不污染判定 |
| P2-B 复盘挑战者扩展 | 触发后选 HOLD 且存在反方证据时，把用户冻结的原话举出（"你当时写的是……"），只引原文不给建议 | 把产品哲学从 ADD 场景扩展到 HOLD 场景，HOLD 才是最常见的真实选择 |
| P2-C 结果对照 | 结局记录（卖出价/收益）与过程统计分开呈现，明确标注"结果不用于评判过程" | 防 P7 结果偏差（用盈亏倒推判断质量），同时沉淀唯一抄不走的数据资产 |
| P2-D 定期复盘报告 | 从快照自动生成季度/年度报告：操作次数、非论点驱动占比、触发后仍持有次数、假设状态变化时间线；一键导出 Markdown | 让半年积累变成可见回报，直接回应"投入在前、回报极晚"的流失曲线 |
| P2-E 首次使用引导 | 三步 onboarding（建论点 → 接数据 → 等触发）+ 一键载入示例论点 | 当前空状态即流失点，引导降低首用成本 |
| P2-F 权重滑条配平 | 假设权重改为滑条自动配平（改一个自动归一其余），替代手动保证和为 1 | PROBLEM.md 已承认录入成本是最大代价，此为直接修复 |

## 四、P3：增长与传播（暂缓，不阻塞价值主线）

- 提醒通道：先做 App 内待办（P1-C），邮件/微信推送排在云同步之后。
- 云同步：D1 本地优先本身是隐私卖点，可把"数据留在本地"作为公开立场，再评估可选的加密同步。
- 公开分享页：单个复盘页只读分享链接（不含持仓数字，只含论点、假设与决策过程），对作品集评审与传播都有效。

## 五、前端展示改造

原则：现有视觉底子（纸质质感、四层分离、THEN vs NOW、验签徽章、行为镜子"只报数不评价"）是产品价值观的可视化，全部保留；改的是信息架构、数据呈现与设备适配。

### 5.1 信息架构（最优先）

- 首页改为**组合总览**：多标的卡片 + 全局待办（P1-C）+ 行为镜子入口。
- 演示模式与真实模式分离：场景推进、T0–T6 时间线只属于演示；真实论点走"刷新观测 → 确认 → 重算"。
- 导航重构：投资组合 / 新建论点 / 待办 / 决策记录 / 行为镜子；证据中心与复盘并入论点详情。

### 5.2 数据可视化

| 现状 | 改为 |
|---|---|
| 指标序列是 CSS 条形图（`height: value*4px`） | 真折线图 + 阈值线 + 跌破标注（31→19→17 跨过 20% 的过程一眼可见，这是产品叙事核心） |
| 健康度 breakdown 是横向条 | 环形或堆叠条，四项扣分来源一图可见 |
| 行为镜子是数字卡片 | 数字保留，补充分布条形图（推动因素、论点驱动占比） |
| 版本对比是并排卡片 | 字段级 diff：置信度、假设状态、规则阈值变化逐项高亮 |

实现约束：当前依赖无图表库，全部用纯 SVG 自绘，不引入重依赖；图表只呈现事实，不添加"趋势向好/恶化"类模型判断。

### 5.3 设备适配

- 当前是桌面优先（固定 232px 侧栏）。持仓记录、被提醒的场景大量发生在手机上。
- 移动端：侧栏 → 底部导航，单列卡片流，复盘点开全屏。
- 验收：375px 宽度下六条主路径（建论点、确认观测、处理待办、复盘、计划外行动、查看决策）均可完成。

### 5.4 技术前置

- `app/components/ThesisKeeperApp.tsx`（832 行）在增加多标的与待办前必须拆分：每页一个组件、路由级取数（Server Components 读数据，客户端组件只做交互）。
- `demo-store` 按页面拆出查询与命令；领域规则（`product-domain.ts`、`demo-domain.ts`）不动，作为共享纯函数层。
- 拆分不改变任何现有不变量，`npm test` 五套测试全绿是拆分完成的定义。

## 六、分期与顺序

| 阶段 | 内容 | 完成定义 |
|---|---|---|
| M1 使用回路 | P1-A 多标的、P1-B 持仓、P1-C 待办、P1-D 观测入口 | 同一账号可对 ≥2 只真实代码的标的完成"建论点 → 确认观测 → 触发 → 复盘 → 快照"全链路 |
| M2 价值沉淀 | P1-E 关闭接力、P2-C 结果对照、P2-D 定期报告、P2-F 权重滑条 | 半年使用后能生成一份有过程有结果的复盘报告 |
| M3 深化与传播 | P2-A 证据抽取、P2-B 挑战者扩展、P2-E 引导、P3 分享页 | 录入成本显著下降（一次粘贴即完成事实抽取）；分享页可公开展示 |

前端改造随各阶段推进：M1 同步完成信息架构重组与移动端适配，M2 完成可视化改造。

## 七、成功指标（与 PROBLEM.md 第六节呼应，保持可证伪）

- 用户建立论点后 30 天内仍有返回（待办中心打开率、观测确认次数），说明"被举回到面前"发生了。
- 规则触发后用户选择"回应"（复盘/异议/延期）而不是"改论点"或离开，说明不可变版本改变了行为而非只增加摩擦。
- 行为镜子可见后，计划外行动占比不再上升且用户能说出那个数字，说明呈现事实产生了作用。
- 观测确认的数值与 Bridge 取数一致、快照验签从未报警，说明确定性出口没有被破坏。

## 八、边界与不做（与现有立场一致）

- 不输出证券推荐、目标价、收益预测或交易指令；待办与报告全部是"你写下的事实 + 你声明的原因"，不追加建议。
- 浮盈亏、持仓数据只展示，不进入健康度与规则判定。
- 港美股、场外基金、实时新闻抓取、公开注册与推送渠道不在本路线图内。
- 行为镜子永远只报计数与中位数，样本不足不给结论；这条不变量在任何新功能里不得放宽。
