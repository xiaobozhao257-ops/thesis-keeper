# Thesis Keeper 论坛需求研究：第一批正式取样

更新日期：2026-08-12

## 研究目标

验证以下问题，而不是只寻找支持产品的帖子：

1. 投资者是否真的会忘记或重写原始投资理由？
2. 行情、盈亏和情绪是否会使交易计划发生漂移？
3. 用户目前如何记录、监控和复盘决策？
4. 现有方法哪里失效？
5. 用户是否需要独立产品，还是表格、备忘录和论坛已经足够？

## 样本与方法

- 样本：30条可追溯观察，来自26个公开页面。
- 平台：雪球10条、集思录9条、Reddit 11条。
- 时间跨度：2015年至2026年。
- 观察单位：一篇用户帖子或一条独立评论；同一讨论中的不同作者观点可分别编码。
- 搜索主题：买入理由、投资逻辑变化、交易日记、短线变长线、计划外交易、复盘、Excel/Word/Notes替代方案、AI与隐私反对意见。
- 纳入标准：自然表达的个人经历、正在使用的工作流、明确工具问题或具体反对意见。
- 排除原则：没有来源的市场统计、纯荐股、重复搬运、只为销售课程或社群的内容。保留一条产品创始人的需求验证帖，但单独标记为D级，不能当作独立需求证据。

证据等级：

- A：用户第一人称描述痛点或失败经历，16条。
- B：用户第一人称展示现有工作流或替代方案，8条。
- C：教育文章、转述案例或具体反对意见，5条。
- D：创始人验证自己产品的帖子，1条。

完整逐条记录见 [forum-observations.csv](research/forum-observations.csv)。

## 主要发现

### 1. 用户表达出来的首要痛点是“计划漂移”，不只是“记忆差”

论坛里更常见的自然语言是：短线做成长线、计划外交易、买入逻辑还在不在、越跌越买、被套后等回本。用户很少主动使用“记忆偏差”这个词。

这说明产品对外表达不宜停留在“帮你记住投资理由”，而应翻译成用户能直接感知的结果：

> 当价格和情绪开始改变你的计划时，及时指出你偏离了什么。

代表案例：

- 雪球用户描述长期交易很快卖出、短线被套后改成长线的典型漂移：[案例](https://xueqiu.com/5223528950/204071405)
- 集思录用户反思越跌越买导致仓位集中，随后又用价格上涨证明逻辑正确：[案例](https://www.jisilu.cn/question/513790?gopage-true__page-1__item_id=5380920)
- 雪球用户公开维护“不做计划外交易”等纪律，但仍记录急于回本和连续乱操作：[案例](https://xueqiu.com/3573057981/350760686)

### 2. 复盘通常发生得太晚，往往由损失触发

强证据案例集中在爆仓、深度浮亏、卖飞或大幅回撤以后。此时用户才重新整理买入理由和心理变化。

- 持有约700天且浮亏约56%后，用户才完整回溯原始买入判断及错过退出窗口的过程：[雪球案例](https://xueqiu.com/8778960057/317684366)
- 期货爆仓和股票卖飞后，用户决定开始记录持仓及心理变化：[雪球案例](https://xueqiu.com/7597950829/336746958)
- 国债ETF经历回撤后，用户才按照买前依据、买后事件重新检查满仓决策：[集思录案例](https://app.jisilu.cn/question/507315?gopage-true__page-3__item_id=5244772)

因此，产品价值点不是更漂亮的事后报告，而是把复核移动到三个时刻：买入前、关键事实变化时、用户准备偏离计划时。

### 3. “有记录”不等于“能改变行为”

最关键的反证来自一名集思录用户：三年写了超过20万字交易日记，但同类心态与执行错误仍会反复发生。[讨论](https://app.jisilu.cn/question/522118?gopage-true__page-1__item_id=5468259)

这直接否定了一个过弱的产品假设：只要帮助投资者持续写日记，他们就会改善决策。

记录要产生行为价值，至少需要：

1. 把错误归纳为可识别模式，例如“亏损后日内换股”“跌破止损后改成长线”。
2. 在下一次相似场景出现前主动召回历史，而不是等用户自行翻日记。
3. 要求用户说明新事实，区分“论点更新”与“为了当前持仓找新理由”。
4. 追踪是否执行，而不只追踪是否写过。

### 4. 用户已有大量免费替代方案，迁移成本是核心竞争风险

当前工作流包括：

- 直接把雪球或集思录长帖当日记；
- Word记录论点，Excel计算估值和收益；
- 每只股票一个带日期的Word文档；
- iCloud Notes按日期记录；
- 自己给Excel接行情或编写脚本。

集思录的工具讨论显示，用户会因为资产类型、费用和查询需求不匹配而从专用软件回到Excel。[多账户讨论](https://www.jisilu.cn/question/482865) Reddit用户也明确认为表格、Google Finance和新闻已经足够，并质疑独立App是否过度设计。[反对意见](https://www.reddit.com/r/investing/comments/1mwrie3/would_you_write_a_investing_journal/)

所以产品不能靠“把日记搬到一个新界面”取胜。必须提供通用工具难以完成的能力：不可覆盖的原始版本、基于个人论点的事件匹配、逻辑漂移检测、相似错误召回和结构化证伪。

### 5. 监控负担是真实需求，但高频提醒可能制造更多噪声

用户会在Excel、Notion、Word、行情、财报和新闻之间切换，也会询问如何持续判断公司是否按原预期发展。另一方面，也有用户指出频繁检查优质公司会诱发过早卖出。

因此提醒机制应当由“个人论点中的少数关键条件”触发，而不是简单推送所有行情和新闻。建议每个论点首版只允许2至4个关键验证条件，并支持财报、重大公告或用户设定日期触发。

### 6. AI的角色必须是“质询和整理”，不能是假装确定的投资裁判

公开评论提出两类信任问题：一是持仓和决策隐私，二是AI容易犯错或迎合用户。还有评论指出，原始论点失效后公司可能产生新的增长逻辑，机械判定“失效即卖出”会犯错。[完整讨论](https://www.reddit.com/r/investing/comments/1mwrie3/would_you_write_a_investing_journal/)

产品设计需要明确：

- AI不输出买入、持有或卖出的确定性指令。
- 每个事实结论附来源、时间和数据口径。
- “原论点失效”只触发重新决策，不直接映射成卖出。
- 新论点可以建立，但必须生成新版本，不能覆盖原始记录。
- 默认私密，支持导出；在没有必要时不要求连接券商账户。

## 需求判断

### 已获得初步支持

1. 自主选股投资者会在行情波动中偏离原计划。
2. 用户确实会记录买入理由、风险、心理和交易结果。
3. 现有记录普遍分散在论坛、文档、表格和行情工具中。
4. 用户需要区分“价格变化”和“投资事实变化”。
5. 单纯日记不足以阻止重复错误，主动召回和执行约束更有价值。

### 尚未被证明

1. 足够多的中国个人投资者愿意持续使用独立App。
2. 用户愿意为该能力付费。
3. AI自动监控比人工季度复核带来显著增量价值。
4. 产品能在不增加焦虑和交易频率的情况下减少计划漂移。
5. 用户愿意录入真实仓位、成本和完整投资理由。

## 建议目标用户

第一阶段聚焦：

- 自主研究并买卖个股；
- 同时持有约5至20只股票；
- 持有周期数周至数年；
- 已用Word、Excel、Notes或论坛记录过投资；
- 经历过“下跌后不知道该坚持还是退出”或“短线被套改成长线”。

暂不作为主目标：

- 只做宽基定投的被动投资者；
- 需要毫秒级执行和大量交易统计的日内交易者；
- 期待AI直接荐股或代替本人做买卖决定的用户。

## 产品需求优先级建议

### P0：验证核心行为价值

1. **60秒决策快照**：支持语音、粘贴或简短输入；最少只要求买入目的、时间范围、两项证据和一项证伪条件。
2. **不可覆盖的原始版本**：允许追加新版本，并清楚展示变化原因。
3. **事件式复核**：财报、关键指标、重大公告或用户指定日期触发，不做泛新闻轰炸。
4. **漂移镜像**：识别时间范围改变、止损后移、无新事实加仓、短线转长线等变化。
5. **历史错误召回**：用户准备做出相似操作时，展示过去同类决策及后果。
6. **过程质量与结果分离**：盈利不自动代表决策正确，亏损也不自动代表论点错误。
7. **隐私与可导出**：默认私密，不强制券商连接，支持导出原始数据。

### 暂不优先

- 以单一“健康分”作为主要判断；
- 通用行情资讯流；
- 社交晒仓和跟单；
- AI直接给出买卖结论；
- 要求用户首次使用就填写完整研究报告。

## 下一轮验证计划

论坛材料适合发现问题，但不能证明采用率和付费意愿。下一轮应进行8至12名目标用户访谈，并结合可操作原型测试。

### 招募筛选

- 过去12个月至少做过5次自主个股决策；
- 当前持有至少3只个股；
- 能展示一种真实记录方式，或能讲述一次计划发生变化的持仓；
- 不以投资内容创作、荐股或销售课程为主要目的。

### 访谈重点

避免直接问“你会不会用这个产品”，改问：

1. 最近一次买入是什么？当时为什么买？这些理由记录在哪里？
2. 最近一次改变持仓计划是什么时候？是什么新事实导致的？
3. 展示你现在的Excel、备忘录、收藏或帖子，实际如何回看？
4. 最近一次没有按计划操作发生了什么？事前有没有可能被阻止？
5. 哪些持仓信息绝不会交给第三方工具？
6. 如果只能保留一个提醒，它应该在什么时刻出现？

### 可证伪指标

- 至少6/10名受访者能提供过去一年内真实的计划漂移案例。
- 至少5/10名受访者当前已有某种决策记录，而不只是口头认可记日记。
- 在原型测试中，至少7/10名用户能在60秒内完成有效决策快照。
- 至少5/10名用户认为“历史错误召回”会让自己暂停或重新检查一次操作。
- 如果多数用户只愿使用表格模板、不愿持续打开独立产品，应考虑插件、浏览器入口或表格增强，而不是继续扩展完整App。

## 当前结论

论坛证据支持“决策逻辑会随价格、情绪和持仓结果漂移”，也支持“用户已有记录与复盘行为”。但它同时否定了“做一个更好看的投资日记就足够”的产品假设。

Thesis Keeper更有机会成立的形态是：

> 一个在关键决策时刻主动召回原始计划、指出逻辑漂移并要求用户面对反证的决策护栏，而不是普通投资笔记或AI荐股工具。
