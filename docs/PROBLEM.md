# Thesis Keeper 要解决的问题

写作日期：2026-08-12。这份文档回答一个问题：为什么要做这个东西。它先于任何功能清单存在，产品里每一条不变量都应该能回溯到这里的某一段。

## 一、问题：人会在事后重写自己的买入理由

投资决策的失败通常不是判断错了，而是判断错了之后没人知道。因为原始判断从来没被固定下来。

一次典型的失败长这样：

1. 买入时的理由是「这家公司所在的行业需求在扩张，收入增速能维持在 25% 以上」。这句话说给自己听，没有写下来。
2. 三个季度后收入增速掉到 17%。这条信息看到了，但当时的注意力在股价上——股价没跌，所以「问题不大」。
3. 半年后被问「你为什么还拿着」，回答变成了「它的估值不高」。这是一条全新的理由，和买入时那条毫无关系。
4. 再往后如果亏了，复盘会写「行业不行了」；如果赚了，复盘会写「我看对了行业」。两种情况下，第一步那句具体的、可被证伪的话都不会再出现。

这里出问题的不是选股能力，是记录能力。行为金融把这几步分别叫做后见之明偏误（第 3 步重构理由）、确认偏误（第 2 步只看支持自己的信息）和处置效应（第 2 步用股价代替基本面做判断依据）。它们的共同前提是：原始判断没有被冻结，所以可以被无痛改写。

## 二、为什么现有工具接不住

| 工具 | 为什么接不住 |
|---|---|
| 券商 App 的自选股与持仓 | 记的是价格与盈亏，不记理由。它强化的正是第 2 步——把注意力钉在股价上 |
| Excel / Notion / 备忘录 | 可以写理由，但可以随时改，且改动无痕。它对第 3 步毫无抵抗力 |
| Wind / Bloomberg 的 note、内部投研平台 | 能做到留痕，但面向机构工作流，散户拿不到也用不起 |
| 雪球、股吧等社区 | 发帖留痕，但激励是获得认同，不是面对自己判错。历史帖子可删可编辑 |
| 通用 AI 对话 | 每次对话是独立的，不持有你上次说过什么，也没有在证据转向时主动回头找你的机制 |

共同的缺口是同一个：没有任何一个工具会在半年后把你当初那句话原封不动地举到你面前，并问「这条还成立吗」。

## 三、这个产品的立场

只做一件事：让原始判断不可改写，并在信息变化时把它举回到用户面前。

由此推出产品里的硬约束，每一条都对应上面某一步：

| 约束 | 对应的失败步骤 |
|---|---|
| 论点确认后不可原地修改，只能新建版本 | 第 3 步。改口可以，但改口这件事本身会留下痕迹 |
| 复盘打开时冻结 THEN 版本，后续版本不能改写该上下文 | 第 3 步。回答「当初为什么买」时看到的必须是当初那句话 |
| 建立论点时必须写下失效条件：什么指标、什么阈值、连续几期 | 第 1 步。把「需求扩张」这种不可证伪的话逼成可监控的数 |
| 买入依据是价格动量 / 消息 / 他人推荐时，必须补一句可被证伪的表述 | 第 1 步。弱依据不禁止，但要留下判错的判据 |
| 逆规则加仓必须写新的反证回应 | 第 2 步。可以加仓，但不能假装没看见 |
| 计划外行动必须声明推动因素，并与「当时还有几条假设成立」并排冻结 | 第 2 步。把「因为股价涨了」和「我的三条假设都不成立了」放在同一屏 |
| 决策快照 canonical JSON + SHA-256，读取时重新验签 | 第 4 步。事后复盘的输入不能被悄悄编辑过 |
| 行为镜子只报计数与中位数，样本不足 3 笔时不给结论 | 第 4 步。用事实代替叙事，但也不用小样本编出新的叙事 |
| 系统不输出证券推荐、目标价、收益预测、交易指令 | 全局。一旦给建议，用户面对的就是系统的判断，不再是自己的 |

最后一条是这个产品最容易被误解的地方，所以说明白：退出条件是用户自己写下来的计划，系统只负责在条件命中时把它拿出来，不评价、不代替、不加建议。

## 四、目标用户：进阶个人投资者

明确选这一侧，另一侧（机构研究员）不做。

选定的用户长这样：自己做研究、单笔持仓周期在半年以上、能说清「我买它是因为什么」但说不出「收入增速连续两个季度低于 20%」、持仓 3 到 10 只、有过至少一次事后想不起自己当初为什么买的经历。

选机构侧会要求多标的、组合视图、投委会材料导出、研报数据源对接，而那一侧的用户已经有留痕系统，缺的不是这个容器。

选进阶个人投资者的直接代价是录入成本必须压到接近零。这决定了 LLM 在产品中的位置（见下节），也是当前版本最需要继续投入的地方：权重归一还需要用户手动配平，证据仍需构造 TEXT/JSON/CSV，`clarificationQuestions` 目前只是把模糊词回抛而没有代替用户完成改写。

## 五、Agent 边界：入口翻译，出口确定

LLM 只在一个地方参与：把用户说的自然语言翻译成可监控、可审计的结构化规则。这一步 Excel 做不到，正则做不到，也正是散户写不出阈值的根本原因。

从规则生成之后，全程不再有模型参与：失效判定是确定性求值，版本不可变，快照验签，缺失数据返回 `DATA_MISSING` 而不做任何推断。这不是没做完，是刻意的——失效判定一旦可以被模型幻觉污染，整个产品的前提就没了。

因此 `LLMModule` 声明的四个模块里只接了编译器一个。剩下三个不接，属于取舍，不属于缺口。

## 六、什么情况下这个产品是失败的

写清楚失败条件，否则这份文档本身也不可证伪：

- 用户建立论点之后再也不回来，说明「被举回到面前」这件事没有真的发生。
- 用户回来了，但每次都是改论点而不是回应论点，说明不可变版本只是增加了摩擦，没有改变行为。
- 行为镜子长期显示计划外行动占比不下降，且用户不觉得那个数字刺眼，说明呈现事实不足以改变习惯，需要的是别的机制。
- 用户把退出条件当成系统建议来执行，说明产品边界的表达失败了，这是最需要警惕的一种。
